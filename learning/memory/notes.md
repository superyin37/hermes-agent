## 阶段 0：概念地图

### 0.1 四种“记得”的来源（2026-09-30）

**用户原始预测：** “A来自上下文，B来自记忆系统中保存用户偏好的部分，C来自记忆系统中关于最近会话/近期任务的部分，D来自模型自动判断创建的skill”。A 是同一聊天追问项目代号，B 是新聊天知道语言偏好，C 是找回上周推迟发布的讨论依据，D 是复用会议整理流程。

**助手回应与源码补充：**

- A 指向当前对话上下文，B 指向持久保存的用户偏好，来源区分合理。内置路径中，`USER.md` 经 `MemoryStore` 的加载快照进入 system prompt；这是助手核对的实现路径，场景本身不能排除其他信息来源。
- C 可以归入广义的记忆能力，但应具体区分 SessionDB 保存的对话历史与 `MEMORY.md` / `USER.md` 中提炼的事实。当前 `session_search` 查询 SQLite 会话数据库，并不限于“最近”会话；用户尚未阅读或运行该检索路径。
- D 把可复用流程对应到 Skill 是合理的；“由模型自动判断创建”只是可能的来源，场景不能证明创建者或创建方式。已安装、手工编写、明确要求创建的技能同样可以被复用。自主创建尚未在 Skills 阶段 5 学习，不据此判断用户已掌握。
- “最终进入模型上下文”与“此前保存于哪一层”是两个维度；B/C/D 的内容也需要进入请求后才能影响回答，不能把“上下文”和“长期存储”视为互斥的答案。

**用户对进程／会话边界的解释：** “那当然是情况一能回答，情况二不能。情况一都恢复原会话了那项目代号不就在上下文里吗，不需要memory也能看到啊。”题设中情况一恢复旧历史，情况二既无旧历史，也无记忆文件中的该事实或历史搜索。用户准确指出恢复的对话本身已经提供事实；情况二缺少可据以回答的信息，不能把偶然猜中算成记忆证据。这里的“不需要 memory”指不依赖长期记忆文件，并不否认旧聊天记录本身经过持久化。

**0.1 小结与证据边界：** 已完成四场景的初始来源区分，并明确进程重启不等于新会话、恢复旧历史不证明读取了长期文件。C 的具体 SessionDB 路径和 D 的创建来源限定仍属于助手补充，不写成用户自行核对的结论。本节只有预测和概念解释，没有运行证据；用户明确认为上一问显而易见，后续不重复考核这个区别。下一步进入 0.2，只读内置快照取值与 system prompt 装配；0.2、0.3 尚未完成。

### 0.2 内置快照与提示词装配（2026-09-30）

**用户源码解释：** 阅读 `tools/memory_tool_store.py::format_for_system_prompt()` 与 `agent/system_prompt.py::_memory_parts()` 后，用户说：“不是自己实时读取USER.md，而是从是**session 加载时冻结的 snapshot** 拿”。这准确指出本次装配代码从 `_system_prompt_snapshot` 取值，并不在取值时重新打开文件。

**助手补充与下一处证据：** 启动路径 `agent/agent_init.py::_init_memory()` 创建 `MemoryStore` 并调用 `load_from_disk()`；后者读出条目、保存 live entries，并将经过加载检查与渲染的文本存入快照。这两处由助手核对，尚待用户阅读。当前先理解普通初始化路径，不将此结论扩大为所有恢复／压缩边界永远不会重载；生命周期细节留到计划相应阶段。

**初始化链的进度与证据边界：** 已有用户对快照取值和装配的源码解释，没有运行、真实请求或缓存命中证据。助手给出初始化与快照建立的代码范围及数据流后，用户要求“继续”，未额外解释该段实现；该链保留为助手补充，不重复考核，也不替用户宣称已完整掌握。之后按计划阅读历史检索与 provider 职责地图，记录如下。

**历史检索与模型／Agent 分工：** 用户看到 `session_db = agent._get_session_db_for_recall()` 后问：“是否说明数据库由agent提供而不是模型自己提供？模型和agent指的是不同侧吧？”用户已正确定位宿主提供 DB 的代码。助手补充：这里的 `agent` 是运行 Hermes 的 Python `AIAgent` 对象，负责会话状态、资源和工具执行；模型是接收消息及工具 schema、生成回答或结构化工具调用的 LLM。模型提交 query 等可序列化参数，宿主将其映射为工具函数参数，并传入实际 DB 对象与当前 session id。两侧是职责边界，不要求部署在不同机器；广义“Agent 系统”又包含模型与这些运行机制，因此不能把所有语境中的 Agent 都理解为模型之外的单个对象。

**历史检索的证据边界：** `inline_tool_executors.py::_session_search()` 的模型参数与宿主资源交接是代码事实，模型调用例子只是示意，没有实际工具运行。当前 `session_search` 返回 SessionDB 消息、不调用辅助 LLM 的结论来自助手核对；主模型仍负责生成查询请求和解读工具结果，不应将“工具内部无 LLM”误读成整条 Agent 流程没有模型。用户随后明确回复“明白，继续推进吧”，确认接受这次术语解释；不据此宣称其已独立追踪完整查询实现。

**Provider 的用户原始解释：** 用户认为外部 memory provider 是“一套外部定义的完整的记忆系统”，这些方法定义接入规范；`system_prompt_block` 提供“长期不变的、静态的说明”，`prefetch` 提供与 query 相关的动态召回。对于“偏好中文答复”，用户明确区分事实本身稳定与取回方式，判断从后端召回仍应走 `prefetch`，新对话交给后端保存走 `sync_turn`。

**助手校准：** 接入规范和读写方向的判断正确。Provider 更准确地是实现 Hermes 契约的插件／适配器，可以自己实现本地存储检索，也可以包装独立服务，不要求每个都是另一套完整系统。“静态”约束会话内既有 system prompt 的稳定性，不表示所有会话永久使用同一段文本。后端的稳定偏好在按需召回场景中仍走 `prefetch`；内置 `USER.md` 的启动快照则是另一条路径，两者不矛盾。是否真的召回该偏好取决于实现和匹配，不能由接口名保证。`sync_turn` 是完成回合交给后端的同步入口，具体保存／提炼策略与落盘完成时间需要看实现；基类默认方法不能证明后端支持了全部能力。

**0.2 小结：** 用户已说明内置快照取值、历史检索 DB 的宿主来源、模型与 Python Agent 的职责，以及 provider 静态提示／动态召回／同步三个接口。本节建立职责地图的目标完成；初始化完整链和查询无 LLM 等细节包含助手补充，未运行实验，也未验证 provider 的实际存储检索。下一步是 0.3 的整体地图与阶段总结，阶段 0 整体暂不标完成。

**源码导航约定：** 后续明确写“只读第 X～Y 行”，避免将“读到 Y 行”误解为从文件开头通读。这是阅读范围的表达澄清，不记为机制理解错误。

### 0.3 整体地图与阶段总结（2026-09-30）

**目标与过程：** 本阶段回答“这次回答可能从哪里获得信息”，承接 Skills 的文件进入上下文与宿主执行工具的认识。用户完成四场景预测、解释恢复历史与长期文件的区别，并通过少量源码锚点说明快照取值、数据库来源与 provider 接口。以下是助手根据这些证据整理的全阶段总结，不代表用户另行完成了独立画图或运行。

| 信息层 | 保存什么／由谁读取 | 进入当前请求的路径与边界 |
| --- | --- | --- |
| 当前消息列表 | 当前对话，宿主组装请求 | 直接作为上下文；重启后恢复旧历史仍可能取得原事实 |
| SessionDB | 持久化会话消息，宿主恢复或搜索 | 恢复历史与 `session_search` 工具结果是不同入口；具体检索实现待阶段 5 |
| MEMORY.md／USER.md | 提炼事实／用户信息，内置 MemoryStore 加载 | 初始化读盘形成快照，再装配 system prompt；后续文件更新与上下文更新不能画等号 |
| Skills | 可复用的程序性知识，技能加载路径读取 | 加载内容进入上下文；能复用不能证明由模型自动创建 |
| 可选 provider | 实现自定的存储，由插件／适配器接入 | 静态说明、按需 prefetch、完成回合 sync_turn 各有职责；具体召回与持久化保证待验证 |
| 压缩摘要 | 对已有上下文的压缩表达 | 生成、保留与生命周期尚未追踪，留阶段 7，不当成已经掌握 |

**结论与收获：** “记得”不是单个存储机制。必须分别问原始信息存在哪里、宿主何时读取、通过哪条路径进入模型请求。内置文件记忆无需假定向量数据库；历史消息也不等于已经提炼的长期事实。模型产生工具调用参数，Python Agent 提供实际 store／DB 等资源。稳定的用户偏好可以通过动态召回取得，事实稳定性与读取时机是两个维度。

**证据边界：** 用户解释与助手源码补充已分别保留在 0.1、0.2；至今无 Memory 运行证据、真实模型请求、provider 后端存储或缓存命中验证。接口存在不能证明某次会话调用过，也不能保证检索命中或写入完成。阶段 0 的职责地图已收束，阶段 1 将通过独立进程的文件读写建立第一条持久化证据；环境准备本身不计作存储闭环完成。
