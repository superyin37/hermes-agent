# Learning Notes Workflow

- 跟随 `learning/` 下的学习计划进行问答时，每次问答结束、继续下一步之前，判断本轮整体内容是否具有长期学习价值。
- 只有涉及关键概念理解、Hermes/Agent 系统机制、重要理解修正，或能长期复用的实验证据与排障结论时，才更新对应模块的 `notes.md`。
- 不要把每次步骤确认、临时环境恢复、普通命令结果、短期权限或网络阻碍、操作分工讨论逐条归档；除非它们改变了实验的可复现性，或构成判断问题所在层的关键证据。
- 对未达到自动归档门槛、但可能对用户有个人学习价值的插入式澄清（例如解释实验包装函数或某条命令的作用），当下不要写入 `notes.md`。当用户稍后明确指示“继续”或要求回到学习计划时，先询问是否要将这一组问答记录；根据用户回答选择记录或跳过，再推进下一步。
- 记录以阶段性关键节点和概念转折为主；满足记录条件时立即更新 `notes.md` 后再推进，不满足时直接继续。
- 保留用户原本的疑问和猜测，区分代码事实、实际运行证据、通用机制解释与待验证推测。
- 只记录实际发生的操作，只勾选确实完成的步骤，不代替用户声称已经理解。
